# Reed 6.0.0 breaking changes

Use this guide when upgrading `@kozmof/reed` from 5.x to 6.0.0.

## Event origin

- Every event a store with events emits now carries `origin`. It names the action that produced the event, lists the other events that action emits, and gives the transaction it ran in. See [event origin](../../spec/05-public-api.md#32-event-origin).
- Each event object gains an `origin` property. Tests that compare whole events with `toEqual` fail on the new key, so compare the fields you need or add `origin: expect.any(Object)`. Code that serializes or clones events now copies the action too, including the chunk bytes of `LOAD_CHUNK` and `LOAD_CHUNKS`. Copy out the fields you need before you keep or send an event.
- Events reach handlers in the same order and at the same time as in 5.x.

## Store event emitter

- `DocumentStoreWithEvents.events` is now a `StoreEventEmitter`. Its handlers receive `StoreEvent` types, where `origin` is always set. Its `emit` accepts only events with an `origin`.
- A call to `doc.events.emit` with an event built without an origin no longer compiles. Pass an `EventOrigin` as the event factory's last argument. A factory given an origin returns a `StoreEvent`.

Pass an origin when you emit an event yourself. Here `action` is the action the event reports.

```ts
import { events, type EventOrigin } from "@kozmof/reed";

const state = doc.getSnapshot();
const origin: EventOrigin = {
  id: 0,
  action,
  types: ["selection-change"],
  transactionId: null,
};
doc.events.emit("selection-change", events.createSelectionChangeEvent(state, state, origin));
```

- Handlers typed with the plain event types, such as `EventHandler<SelectionChangeEvent>`, still compile with `addEventListener`, `removeEventListener`, and `events.addEventListener`.
- A store wrapper or test double that implements `DocumentStoreWithEvents` and sets `events` to `events.createEventEmitter()` no longer compiles. Use `events.createStoreEventEmitter()` instead. A wrapper that passes on the inner store's `events` needs no change.
- Emitters from `events.createEventEmitter` keep the `DocumentEventEmitter` type, so `origin` stays optional on them. Assigning `doc.events` to a `DocumentEventEmitter` still compiles. An event without an origin emitted through it no longer reaches handlers. The store reports it through its logger and drops it.
