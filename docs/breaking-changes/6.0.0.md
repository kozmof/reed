# Reed 6.0.0 breaking changes

Use this guide when upgrading `@kozmof/reed` from 5.x to 6.0.0.

## Event origin

Every event from `DocumentStoreWithEvents` now includes `origin`. Use it to find the action that produced the event, the event types that action emits, and the outermost transaction open when the action was dispatched. See [event origin](../../spec/05-public-api.md#32-event-origin).

- Update tests that use `toEqual` to compare whole events. Compare the fields you need or add `origin: expect.any(Object)` to the expected event.
- Pick the fields you need before storing or sending events. Cloning or serializing a whole event also copies or serializes its action, including the chunk bytes for `LOAD_CHUNK` and `LOAD_CHUNKS`.

Event delivery order and timing are the same as in 5.x.

## Store event emitter

`DocumentStoreWithEvents.events` now uses `StoreEventEmitter`. Its handlers receive `StoreEvent` values, and its `emit` method requires an event with an origin.

When calling `doc.events.emit` directly, pass an `EventOrigin` as the last argument to the event factory. The factory then returns a `StoreEvent`. In this example, `action` is the action the event reports.

```ts
import { events, type EventOrigin } from "@kozmof/reed";

const state = doc.getSnapshot();
const origin: EventOrigin = {
  id: 0,
  action,
  types: ["selection-change"],
  transactionId: null,
};
doc.events.emit("selection-change", events.createSelectionChangeEvent(state, state, origin));
```

- Handlers typed with the plain event types, such as `EventHandler<SelectionChangeEvent>`, still compile with `addEventListener`, `removeEventListener`, and `events.addEventListener`.
- Use `events.createStoreEventEmitter()` in wrappers or test doubles that implement `DocumentStoreWithEvents` and create their own emitter. Wrappers can continue to forward the inner store's `events`.
- Emitters from `events.createEventEmitter` keep the `DocumentEventEmitter` type, so `origin` stays optional on them.
- Assigning `doc.events` to a `DocumentEventEmitter` still compiles. An event without an origin emitted through that variable no longer reaches handlers. The store reports it through its logger and drops it.
